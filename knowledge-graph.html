ProofOfWork 工作量证明
BLC/ProofOfWork.go（002-007）
Bitcoin 式 PoW 实现：

难度目标 targetBit = 16（Hash 前16位为0）
使用 math/big.Int 比较，避免整数溢出。

NewProofOfWork(block) → target = 1 << (256-16)
Run() → 递增 nonce 直至 hash < target
IsValid() → 验证现有 hash 是否合法

007版本改进：prepareData 使用 HashTransactions() 而非原始 Data。

💡 核心区块链概念

🔐 SHA-256 哈希

每个区块的 Hash 由 Height + PrevBlockHash + Data + Timestamp + Nonce 拼接后经 SHA-256 计算得到，保证不可篡改性。若修改任意区块内容，其 Hash 改变， 后续所有区块的 PrevBlockHash 均失效。

⛏️ 工作量证明（PoW）

要求生成的 Hash 前 targetBit=16 位为0，即 Hash 值小于目标值 target = 1 << 240。矿工不断递增 nonce 直到找到满足条件的 Hash，确保出块需要计算代价，防止恶意分叉。

🔗 链式结构

每个区块存储前一个区块的 Hash（PrevBlockHash），形成单向链表。 创世块的 PrevBlockHash 为 32字节全0。 遍历时从 Tip（最新块）反向追溯至创世块。

💾 BoltDB 持久化

使用嵌入式 K-V 数据库 BoltDB 存储区块数据。 Key = 区块Hash，Value = gob 序列化的区块字节； 特殊键 "l" 存储最新区块的 Hash，作为链的"游标"。

💸 UTXO 模型

007 模块引入 UTXO（Unspent Transaction Output）框架。 区块不再存储字符串数据，而是存储 []*Transaction。 每笔交易有输入（引用已有 UTXO）和输出（生成新 UTXO）， 当前仅定义了框架，TxInput / TxOutput 待完善。

📝 gob 序列化

使用 Go 标准库 encoding/gob 将 Block 结构体编码为字节数组， 用于 BoltDB 存储和网络传输。Serialize() 编码， DeserializeBlock() 解码，配合 bytes.Buffer 使用。
